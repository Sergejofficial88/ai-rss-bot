# История изменений

## 1.1.0 — 2026-09-22

Исправления по итогам первых запусков.

### Исправлено

- **Потерянное логирование (критично).** Автоформат `biome check --write --unsafe`
  удалял все вызовы `console.*`: у правила `noConsole` деструктивный unsafe-автофикс.
  Из-за этого ошибки ИИ и Telegram не попадали в логи, и понять, работает ли Gemini
  на самом деле, было невозможно. Правило отключено, логирование восстановлено,
  `--unsafe` для этого проекта больше не применяется.
- **Кнопки не были привязаны к репозиториям.** 8 проектов × 2 кнопки давали сетку,
  в которой невозможно понять, какая кнопка к какому проекту относится.
  Теперь у каждого проекта **своя кнопка с его именем**, а действия выполняются
  в карточке проекта: открыть на GitHub, спросить ИИ, вернуться к списку.
- **Возможные дубли в списке** при пагинации GraphQL. Добавлена дедупликация по
  `owner/repo`, количество отброшенных дублей выводится в `/status` и в отчёте `/check`.
- **Устаревшая модель Gemini.** `gemini-2.5-flash` устарел; по умолчанию теперь
  `gemini-3.8-flash`, а модель задаётся переменной `GEMINI_MODEL` без правки кода.
- **Молчаливый откат на резервный провайдер.** Теперь Gemini пробуется через два API
  (`generateContent` и новый `interactions`), каждая ошибка логируется,
  а в ответе указывается, какая модель его подготовила.
- **Валидация `owner/repo`** пропускала `..` и не ограничивала длину сегментов
  (владелец ≤ 39, репозиторий ≤ 100).

### Добавлено

- Команда **`/ai`** — проверка связи с Gemini, список доступных ключу моделей
  и подсказка, как сменить модель.
- Подпись модели под каждым ИИ-ответом — видно, кто именно ответил.
- Строка «GitHub сообщает: N» в списке и `/status` для сверки количества.

## 1.0.0 — 2026-09-22

Полная переработка бота. Было: проверка первых 10 избранных репозиториев, список
отдельным сообщением на каждый проект, вопрос к ИИ через копирование команды.

### Исправлено

- **Проверялись только первые 10 репозиториев.** Причина — жёстко заданный `per_page=10`.
  Простое снятие лимита сломало бы воркер: 40 репозиториев давали 41 внешний запрос
  при лимите Workers Free в 50. Перешли на **GitHub GraphQL** — один запрос отдаёт
  весь список избранного вместе с последними релизами.
- **Список присылался по сообщению на репозиторий** (40 проектов = 40 запросов Telegram).
  Теперь одно сообщение с постраничной навигацией по 8 проектов.
- **Вопрос к ИИ требовал копировать команду** в новое сообщение. Теперь кнопка
  «💬 Спросить ИИ» открывает поле ввода ответа (Force Reply).
- **Первый запуск вызвал бы лавину уведомлений.** Добавлена базовая инициализация:
  состояние фиксируется молча, приходит одно сообщение.
- **Эндпоинт `/run` и вебхук были без защиты.** Добавлены `RUN_TOKEN`
  и `TELEGRAM_WEBHOOK_SECRET`.
- **Ошибки отправки в Telegram не логировались.** Теперь ответ API проверяется.
- **Ввод `/ask` подставлялся в URL без проверки.** Добавлена валидация `owner/repo`.
- **Callback-кнопки не проверяли отправителя.**

### Изменено

- ИИ-провайдер: **Gemini 2.5 Flash** как основной, **Workers AI** (`llama-3.3-70b`)
  как резерв. Без ключа `GEMINI_API_KEY` работает только Workers AI.
- Расписание: каждые 3 часа → **каждые 15 минут**.
- Список избранного кэшируется в KV на 5 минут, чтобы навигация не дёргала GitHub.
- Код разбит на 8 модулей вместо одного файла.

### Добавлено

- Команда `/status` — число проектов, время последней проверки, активный ИИ.
- Дайджест для остатка уведомлений, чтобы не выходить за лимит внешних запросов.
- Ограничители рассылки за прогон (`MAX_*_PER_RUN` в `src/config.js`).
