# realise-rss-ai

Telegram-бот на Cloudflare Workers: следит за релизами **избранных (starred)** GitHub-репозиториев,
присылает уведомления с ИИ-разбором и отвечает на вопросы по коду проекта.

---

## Что было исправлено и улучшено

| # | Проблема | Решение |
|---|----------|---------|
| 1 | **Проверялись только первые 10 репозиториев** (`per_page=10`) | Переход на **GitHub GraphQL**: один запрос отдаёт список избранного вместе с последними релизами |
| 2 | Наивное снятие лимита сломало бы воркер: 41 запрос на 40 репозиториев + Telegram при лимите Free в **50** | GraphQL сокращает это до **1 запроса** на весь список |
| 3 | **Список присылался по сообщению на репозиторий** (40 сообщений = 40 запросов) | Одно сообщение с постраничной навигацией (8 на страницу, кнопки ◀ ▶) |
| 4 | Вопрос к ИИ требовал **копировать команду** в новое сообщение | **Force Reply**: кнопка «💬 Спросить ИИ» сразу открывает поле ввода |
| 5 | Первый запуск вызвал бы лавину уведомлений | **Базовая инициализация**: состояние фиксируется молча, приходит одно сообщение |
| 6 | Эндпоинт `/run` и вебхук были **без защиты** | Поддержка `RUN_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` |
| 7 | Ошибки отправки в Telegram никак не логировались | Проверка ответа API и запись ошибок в лог |
| 8 | Ввод `/ask` подставлялся в URL без проверки | Валидация формата `owner/repo` |
| 9 | Callback-кнопки не проверяли отправителя | Проверка владельца перед обработкой |
| 10 | Слабая модель `llama-3.1-8b` | **Gemini 2.5 Flash** как основная, **Workers AI** (`llama-3.3-70b`) как резерв |

## Структура проекта

```
src/
├── index.js       — точка входа: Cron-обработчик и вебхук Telegram
├── config.js      — константы, лимиты, ключи KV
├── github.js      — GitHub GraphQL и REST запросы
├── ai.js          — провайдеры ИИ (Gemini + Workers AI) и промпты
├── tracker.js     — основная логика проверки релизов и рассылки

└── utils.js       — вспомогательные функции

```

## Требуемые секреты

Уже настроены в дашборде, значения дублировать никуда не нужно:

| Имя | Обязательно | Назначение |
|-----|-------------|------------|
| `TELEGRAM_BOT_TOKEN` | да | Токен бота от @BotFather |
| `ALLOWED_TELEGRAM_ID` | да | Ваш Telegram ID (единственный, кому бот отвечает) |
| `GITHUB_USERNAME` | да | Логин GitHub, чьё избранное отслеживаем |
| `GITHUB_TOKEN` | да | Personal Access Token (scope `read:user`) |
| `GEMINI_API_KEY` | нет | Ключ Google AI Studio. Без него работает Workers AI |
| `RUN_TOKEN` | нет | Защищает ручной запуск `/run?token=...` |
| `TELEGRAM_WEBHOOK_SECRET` | нет | Проверка подлинности вебхука Telegram |

## Шаг 1. Узнать ID KV-пространства

1. Откройте [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **KV**
2. Нажмите на пространство `RELEASES_KV`
3. Скопируйте **Namespace ID** (32 символа)
4. Вставьте его в `wrangler.jsonc` вместо `REPLACE_WITH_KV_NAMESPACE_ID`

> ⚠️ Из дашборда копируйте **только значение `id`**. Кнопка «копировать» там показывает
> заглушку с именем `KV_BINDING` — его менять не нужно. Поле `binding` в `wrangler.jsonc`
> должно остаться `RELEASES_KV`, потому что именно это имя читает код (`env.RELEASES_KV`).

---

## Шаг 2. Добавить секреты (необязательно, но рекомендуется)

**Секреты принципиально не хранятся в `wrangler.jsonc`** — этот файл уходит в GitHub,
и ключи стали бы публичными. Поэтому они задаются отдельно от конфигурации.

Через дашборд: **Worker → Settings → Variables and secrets → Add → тип Secret**

| Секрет | Зачем | Обязателен |
|--------|-------|------------|
| `GEMINI_API_KEY` | Ключ Google AI Studio. Без него ИИ работает на Workers AI | нет |
| `RUN_TOKEN` | Защищает ручной запуск `/run?token=...` | нет |
| `TELEGRAM_WEBHOOK_SECRET` | Отсекает поддельные обновления вебхука | нет |

Или через CLI:

```bash
npx wrangler secret put GEMINI_API_KEY
npx wrangler secret put RUN_TOKEN
```

> Четыре основных секрета (`TELEGRAM_BOT_TOKEN`, `GITHUB_TOKEN`, `GITHUB_USERNAME`,
> `ALLOWED_TELEGRAM_ID`) у вас уже настроены — трогать их не нужно.
> Если `TELEGRAM_WEBHOOK_SECRET` не задавать, проверка секрета просто не выполняется,
> и текущий вебхук продолжит работать как раньше.

## Шаг 3. Установка и локальная проверка

```bash
npm install
cp .dev.vars.example .dev.vars   # заполнить своими значениями
npm run dev                      # локальный запуск на http://localhost:8787
```

Проверить логику можно открыв `http://localhost:8787/run` — выполнится одна проверка.

## Шаг 4. Публикация

### Вариант А. Через GitHub (рекомендуется — появляется история версий)

Локальный репозиторий уже создан и первый коммит сделан. Осталось создать
**пустой** репозиторий на GitHub (без README и без .gitignore) и выполнить
в папке `ai-rss-bot`:

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/ai-rss-bot.git
git push -u origin main
```

При первом push Git запросит логин и пароль. В качестве пароля нужен
**Personal Access Token** (тот же тип, что уже используется в секрете `GITHUB_TOKEN`).

### Вариант Б. Через Wrangler (быстро, без GitHub)

```bash
npx wrangler login
npm run deploy
```

Затем в дашборде: **Worker → Settings → Builds → Git repository → Connect**,
выбрать репозиторий. После этого каждый `git push` будет автоматически деплоить новую версию,
а **Edit code** в дашборде станет недоступен — правки идут только через Git.

> Секреты при этом сохраняются и не требуют повторной настройки.

## Шаг 5. Настроить вебхук Telegram

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d "url=https://realise-rss-ai.sergotv888.workers.dev/" \
  -d "secret_token=<ВАШ_TELEGRAM_WEBHOOK_SECRET>"
```

Если `TELEGRAM_WEBHOOK_SECRET` не задан в секретах воркера, параметр `secret_token`
можно не передавать — проверка просто не выполняется.

Проверить текущий вебхук:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

## Расписание

В `wrangler.jsonc` задано `*/15 * * * *` — проверка каждые 15 минут.

| Интервал | Полных обходов в сутки |
|----------|------------------------|
| `*/15 * * * *` | 96 |
| `*/30 * * * *` | 48 |
| `0 */3 * * *` | 8 |

Для 40 репозиториев даже 15-минутный интервал расходует ничтожную долю квоты.

## Как уложиться в лимиты Workers Free

Официальные ограничения бесплатного плана:

| Лимит | Значение | Наш расход за прогон |
|-------|----------|----------------------|
| Внешние запросы | **50** | 1 (GitHub GraphQL) + уведомления в Telegram |
| Запросы к сервисам Cloudflare | 1 000 | ~80 чтений и записей KV |
| CPU на прогон | **10 мс** | ~1 мс (разбор ~30 КБ JSON) |
| Длительность Cron | 15 мин | ~1–3 секунды |

Защитные ограничители в `src/config.js`:

- `MAX_REPO_NOTICES_PER_RUN = 5` — уведомлений о новых проектах за прогон
- `MAX_RELEASE_NOTICES_PER_RUN = 5` — уведомлений о релизах за прогон
- `MAX_AI_CALLS_PER_RUN = 8` — обращений к ИИ за прогон
- Остальные обновления уходят **одним дайджестом**

## Команды бота

| Команда | Действие |
|---------|----------|
| `/start`, `/help` | Справка и меню |
| `🔄 Проверить релизы`, `/check` | Ручная проверка |
| `📋 Список Starred-репо`, `/repos` | Постраничный список проектов |
| `💬 Спросить ИИ` | Кнопка: вопрос вводится ответом на сообщение |
| `/ask owner/repo вопрос` | Тот же вопрос одной командой |
| `/status` | Состояние: число проектов, время последней проверки, активный ИИ |

## Первый запуск после обновления

При первом прогоне бот зафиксирует текущее состояние **без рассылки** и пришлёт
одно сообщение «✅ База инициализирована» со списком взятых под наблюдение репозиториев.
Это сделано специально: иначе пришло бы по уведомлению на каждый проект.
